CREATOR PROTOCOL

The publishing process

Every Creator submission follows the same basic workflow so projects are understandable, maintainable and safe for the community.

01

Request Creator access

Contact the Horizon team through Discord. Present yourself, your experience and the type of content you intend to create. Creator access may require a Creator code or approval.

02

Build and test your project

Develop the content locally and test it before submission. Weapons, missions, strikes, raids and other projects should be in a usable state rather than being an untested archive.

03

Prepare the package

Keep the release clean. Include only the files required by the project and remove private information, credentials, unrelated executables and development leftovers.

04

Document everything

Provide the project name, creator name, description, category, version, installation instructions, dependencies, compatibility information, known limitations and useful screenshots or previews.

05

Submit for review

Send the project through the Creator publishing workflow. A submission is reviewed before it becomes publicly discoverable in the Workshop.

06

Moderation and validation

The team checks the project structure, metadata and basic safety requirements. Suspicious files, malicious behavior, credential harvesting, destructive content or misleading information can result in rejection or a request for changes.

07

Version and changelog

Give every release a clear version and explain what changed. Do not silently replace a published build with an unrelated version.

08

Maintain your project

Keep compatibility and installation information current. If a release becomes broken or unsafe, report it and provide a corrected version.
